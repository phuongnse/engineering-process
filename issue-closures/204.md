# [consumer-process][engineering-process][2.4.0][metadata-ci-repetition] Avoid unconditional full CI reruns for PR metadata changes

## Request

### Context

The engineering-process self-consumer reported that pull-request metadata edits could rerun the full CI matrix even when source behavior was unchanged, increasing cost without adding relevant behavioral evidence.

### Expected outcome

CI preserves the required checks and consumer policy while avoiding redundant matrix execution for metadata-only pull-request edits.

## Evidence and scope

### Evidence

The CI routing correction was merged in PR #206 at commit 6abb2b9. The v2.5.0 release recorded the accepted #197-#205 consumer change, and the v2.6.0 adoption PR verified the current self-consumer after adoption.

### Scope

Pull-request CI event routing for metadata-only changes; no skipped required checks for source changes, no weakened branch protection, and no unrelated workflow redesign.

### Acceptance criteria

Metadata-only pull-request updates avoid redundant matrix reruns while source changes retain the required CI coverage, and the released behavior is adopted and verified by the consumer.
